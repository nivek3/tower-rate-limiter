# PostgreSQL GCRA 优化前后压力测试

测试日期：2026-11-01（Asia/Shanghai）。源码基于 `0ef5acf`，优化后包含当前未提交修改；原始 SQL 快照和哈希已保存。

## 结论

过期清理查询的收益明确：10 万条未过期记录、零过期记录时，旧查询扫描并过滤全部 10 万行，新查询直接使用过期索引的范围条件返回空集。
三轮耗时中位数由 **8.696 ms 降至 0.059 ms**。这是该测试数据下的查询耗时，不是整体服务的加速比例。

已有用户的锁定读取路径在长轮复测中取得约 9% 的吞吐提升。热点用户的长轮结果有升有降，未显示稳定收益；同一个 key 的行锁串行化仍然是明显限制。
共完成 **60 轮、1,642,763 次调用，失败事务为 0**。另有 5 个 PostgreSQL 行为测试、3 个接口测试通过，包含首次并发创建和清理竞态。

## 测试条件

- PostgreSQL 17.10，独立临时 Docker 容器，限制 1 CPU、512 MiB 内存。
- 压测客户端使用另一个容器，限制 1 CPU、256 MiB 内存、2 个 pgbench 线程；共享网络命名空间，通过 TCP loopback 连接。
- `fsync=on`、`synchronous_commit=on`；prepared 协议，默认事务隔离级别，无失败自动重试。
- 普通场景使用 1 微秒补充间隔、总突发容量 10,000,000，确保测量放行路径；拒绝场景使用 60 秒间隔、容量 1，并预先耗尽。
- 每次调用检查是否符合预期放行结果、剩余额度范围及等待时间；新用户场景检查状态行数等于成功调用数，拒绝场景检查 TAT 未推进。
- 每轮重置对应状态表，修改前后交替顺序；除新用户场景外，均预热 1 秒。延迟分位数来自全部成功调用的逐请求日志，无抽样。
- 测量数据库函数，**不包含 Rust 响应解析、连接池排队、Tower 或 HTTP**。

## 长轮复测：每轮 15 秒，各重复 3 次

短轮出现波动和热点场景中位数下降，因此单独延长这两项测试。下表分别取各版本三轮的中位数。

| 场景 | 并发连接 | 修改前 次/秒 | 修改后 次/秒 | 吞吐变化 | 修改前 p95 | 修改后 p95 |
|---|---:|---:|---:|---:|---:|---:|
| 已有用户，10,000 个 key | 64 | 7,154 | 7,803 | +9.1% | 62.077 ms | 58.879 ms |
| 同一热点用户，全部放行 | 16 | 1,264 | 1,235 | -2.2% | 32.498 ms | 34.892 ms |

长轮的原始吞吐范围：

- 已有用户，10,000 个 key，64 并发，修改前：7,006～7,223 次/秒。
- 已有用户，10,000 个 key，64 并发，修改后：7,241～7,939 次/秒。
- 同一热点用户，全部放行，16 并发，修改前：1,257～1,324 次/秒。
- 同一热点用户，全部放行，16 并发，修改后：1,198～1,404 次/秒。

## 清理查询执行计划

- 旧查询：`expires_at <= clock_timestamp()`，索引扫描后过滤 100,000 行；耗时中位数 8.696 ms。
- 新查询：`expires_at <= statement_timestamp()`，具有过期范围 `Index Cond`；耗时中位数 0.059 ms。
- 两个查询使用同一张表、相同的 100,000 条未过期记录，交替执行，各重复 3 次；没有删除任何记录。
- 原始 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` 保存在 `raw/cleanup-*.json`。

## 结果边界

这是开发机上的短时、闭环压测。Docker CPU 限额不是独占 CPU，宿主机还有其他容器运行；环境波动、磁盘和后台维护都可能影响结果。没有模拟业务查询共用数据库、网络故障或长时间运行，因此不能据此保证生产容量。
尤其是单个热点 key，64 并发的短轮吞吐仅约 480 次/秒，p95 约 0.38 秒；分散 key 的吞吐不能代表这种负载。拒绝请求也要访问数据库并获取行锁。
没有压测 Redis、Memory 或端到端 HTTP，也没有运行全功能测试或格式化。此次只对 PostgreSQL 优化及相关回归做验证。

## 归档文件

- `environment.json`：版本、资源限制、源码哈希、测试配置及总调用数。
- `before.sql` / `after.sql`：对比的函数及表结构快照，仅替换隔离 schema 名称。
- `workloads/`：实际使用的 pgbench 脚本。
- `summary.json`：48 轮初测记录；`confirmation.json`：12 轮长轮记录。
- `cleanup.json`、`raw/`：清理执行计划、每轮 pgbench 原始汇总。
- `verification.json`：Rust 回归测试结果。
- 逐请求延迟日志位于 `environment.json` 记录的临时目录，未将大体积日志加入仓库。
